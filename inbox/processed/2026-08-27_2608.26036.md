# Paper

## One-line Summary

LLMエージェントを最終回答の正しさだけで評価するのではなく、
「その回答に至った計算過程が実行可能・再現可能・監査可能か」を
Trace Integrityとして評価すべきだと提案する研究。

## Research Question

正しい最終回答を生成したLLM Data Agentであっても、
内部の計算・SQL・操作手順が誤っているケースを
どのように検出・評価すべきか。

## Data

BIRD Mini-Devから100例を使用。

## Methodology

以下3条件を比較。

1. Direct SQL
2. Operation Summary + SQL
3. Contract-First SQL

評価指標として、

- Answer Accuracy
- Execution Success
- Trace Integrity Pass Rate
- Answer-Trace Consistency
- CAIT Rate

を使用。

CAIT:
Correct Answer / Invalid Trace

つまり、
「答えは合っているが計算過程は誤っている」
ケースを明示的に測定する。

## Main Findings

Answer AccuracyとTrace Integrityは別物だった。

Direct SQL:

- Answer Accuracy: 20.0%
- Trace Integrity Pass: 39.0%
- CAIT: 55.0%

Operation Summary + SQL:

- Answer Accuracy: 22.0%
- Trace Integrity Pass: 43.0%
- CAIT: 59.1%

Contract-First SQL:

- Answer Accuracy: 24.0%
- Trace Integrity Pass: 40.0%
- CAIT: 45.8%

## Evidence

- 正答であっても、その計算Traceがinvalidであるケースが多数存在する。
- CAIT Rateは3方式すべてで高い。
- Execution Contractとして、schema、operator plan、assumption、
  executable query、verification status、final answerとの対応を
  構造化することを提案している。
- 失敗したTraceをRegression Testとして再利用することも提案されている。

## Limitations

- BIRD Mini-Dev 100例のみ。
- 使用モデルは1モデル。
- 固定されたprompt / execution環境。
- deterministic validatorは完全なsemantic equivalenceを保証しない。

## Interpretation

ArxivResearchAgentのようなAIエージェントでは、
「生成されたKnowledgeがもっともらしいか」だけでなく、

Input
→ Evidence
→ Interpretation
→ Insight
→ Hypothesis

という変換関係そのものを監査可能なartifactとして保存する設計が重要になる。

これは今回の
Structured Markdown + Validation + Git
という設計思想と非常に整合する。

## Potential Applications

- AI Agent生成物の自動検証
- データマート開発Agentの監査
- Research Agentのprovenance管理
- backtest Agentの再現性検証
- agent outputのregression test化

# Insights

## Insight 1

### Statement

Agent評価ではOutput CorrectnessとProcess Correctnessを
別の品質軸として扱う必要がある。

### Why It Matters

偶然正しい結果を出したAgentを高品質と判定することを防げる。

### Supporting Evidence

CAIT Rateが45.8〜59.1%存在した。

### Confidence

high

## Insight 2

### Statement

Agentが生成する最終成果物だけでなく、
実行契約・入力・処理・検証結果を構造化して保存することで、
失敗事例そのものを将来の評価データに変換できる。

### Confidence

high

# Hypotheses

## Hypothesis 1

### Statement

Research Agentについても、
最終Insightの品質だけでなくEvidence→InsightのTrace Integrityを
評価するとhallucinationや根拠飛躍をより高精度に検出できる。

### Mechanism

EvidenceとInferenceの対応関係をstructured artifact化し、
Insightごとにsupporting evidenceを要求する。

### Required Data

- Paper Evidence
- Insight
- Evidence-to-Insight links
- human validation result
- factual error labels

### Proposed Test

同一Research Agentについて

A. 最終回答のみ評価
B. Evidence-to-Insight traceも評価

の2方式で、
後から人間が発見する誤りの検出率を比較する。
